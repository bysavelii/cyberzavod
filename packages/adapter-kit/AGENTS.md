# Общая часть адаптеров (packages/adapter-kit)

Код, который нужен каждому адаптеру агента одинаково: владение сгенерированными файлами, манифест, файл хуков, сами хуки записи, начала хода и остановки, модель сырого журнала, черновик и публикация записи сессии, шаблоны и тексты, общие для агентов. Пакет не называет ни одного агента: имя агента, его модели, пути его файлов и формат его настроек задаёт сам адаптер (`adapters/claude`, `adapters/codex`), а кит получает их параметрами. Зависит от ядра и хранилища, адаптеры зависят от него, CLI — только через адаптеры.

## Правила

- **Отметки и владение** (`generate/marks.ts`, `generate/file-plan.ts`). Сгенерированный файл несёт отметку `GENERATED_MARK` (в Markdown — `MARKDOWN_GENERATED_COMMENT`, в TOML и YAML — `HASH_GENERATED_COMMENT`); прежняя русская `LEGACY_GENERATED_MARK` (до 0.8.0) тоже узнаётся. `ownershipOf` решает по манифесту и отметке: `missing`, `generated`, `edited` (исправлен руками), `human`. `planSyncFiles` строит план (`SyncPlan`: добавить, обновить, удалить, конфликты, исправленные руками), `applySyncPlan` его пишет, `requireWritable` бросает `KitError`, если план упирается в чужие файлы. Перевод строк `\r\n` расхождением не считается.
- **Манифест** (`generate/manifest.ts`): `.cyberzavod/generated.json` (`schemaVersion: 1`) — хеш sha256 каждого записанного файла и запреты, которые адаптер сам дописал в настройки. Один манифест на проект: в нём файлы одного агента, потому что агент проекта один.
- **Файл хуков** (`generate/hook-config.ts`): формат `{hooks: {Событие: [{matcher?, hooks: [обработчик]}]}}` общий у Claude Code и Codex. Свои обработчики узнаются по началу команды (`npx … cyberzavod@<версия> hook …`, любая версия, а также прежний вшитый CLI) и заменяются; чужие и прочие ключи остаются. `inPosixShell` оборачивает готовую команду в `sh -c '…'`, если агент отдаёт её логин-оболочке человека (Codex). `hookCommand` собирает команду из запускающей части (её выбирает адаптер), версии, имени хука, необязательного `agentFlag` и запасного пути на любой ненулевой код (`SKIP_ON_FAILURE`, `stopFailureCommand`). `mergedHooks`, `withoutOwnHooks`, `inspectHooks` (`installed`, `missing`, `otherVersion`, `incomplete`) — чистые функции над `Settings`.
- **Отключение** (`generate/disconnect-plan.ts`): `plannedDisconnectFiles` и `applyDisconnect` — удалить нетронутые файлы и манифест, оставить исправленные руками, убрать опустевшие каталоги внутри границ адаптера, записать или удалить файл настроек. Что убрать из самих настроек, решает адаптер.
- **Тексты процесса** (`generate/workflow-text.ts`, `generate/template.ts`): таблица этапов, секции этапов, абзацы рабочих правил для `CLAUDE.md` и `developer_instructions`, подстановки шаблонов `{{generated}}`, `{{cli}}`, `{{raw}}`, `{{drafts}}`, `{{todo}}`; неизвестная подстановка — ошибка. Всё, что зависит от агента (название вызова `/feature` или `$feature`, каталог ролей), приходит параметром.
- **Хуки** (`hooks/`): общие для агентов `record` (`recordEvent(context, source)`, `source: RawEventSource` — имя агента для `capture/<агент>/raw/` и функция «нагрузка → событие»; хук ставит проект на `session_start`, забирает отметку `human-call` на промпте человека), `turn-start` (`startTurn`) и `stop` (`gateStop`), состояние между вызовами (`state.ts`), отпечаток кода (`fingerprint.ts`), проверки проекта (`checks.ts`). `HookContext` — нагрузка, каталог проекта, каталог состояния и `KitMessages`; результат — `HookOutcome`. Отказ остановки — JSON `block` с кодом 0, причины — в доках `stop-gate.ts`. Нагрузки каждого агента в события превращает сам адаптер, кит нагрузок не знает.
- **Сырой журнал** (`capture/raw-event.ts`): модель событий `RawEvent` (`session_start`, `prompt`, `question_answer`, `tool`, `subagent_start`, `subagent_stop`, `subagent_report`, `stop`; у `tool` необязательный `callId` — для агентов, чей транскрипт называет вызов по id; у `subagent_start` необязательный `transcriptPath` — для агентов, чей хук начала отдаёт транскрипт сабагента: из него черновик берёт токены и отчёт запуска, который оборвали до остановки), чтение журнала `parseRawLog`, общие помощники нагрузок (`verdictOf`, `subagentNameOf`, `withOptional`, `MAX_COMMAND_LENGTH`). Новый вид события — новая строка в `RAW_EVENT_SHAPES`, без неё не соберётся. `capture/service-messages.ts` — `isHumanPrompt`: по началу сообщения отличает слова человека от служебных (`SERVICE_MESSAGE_PREFIXES`: Claude Code и Codex).
- **Имя хука в команде** (`hook-config.ts`): форму `npx … cyberzavod@<версия> hook <имя>`, голую или в `sh -c '…'`, знает одно место — `NPX_HANDLER_PATTERN`; `isOwnHandler`, `inspectHooks` и `hookNameOf` читают команду им.
- **Проект** (`paths.ts`): `requireProject`, `locateProject`, `findProjectId` (проект каталога вверх до маркера; битый конфиг — предупреждение), `newestFile`, каталоги `capture/<агент>/…` (`captureDirectories`); нет проекта — `KitError`.
- **Черновик и публикация записи** (`capture/`, `commands/`). От агента зависит только разбор транскрипта, остальное общее. Разбор формата — `TranscriptFormat` (`capture/transcripts.ts`): токены по сообщениям модели (одна функция `tokenUsages`: у каждого сообщения `model`, `breakdown` по видам и необязательное время `ts`; счётчик `tokens` формат не считает — его даёт `countedTokensOf` ядра), модель по ходам (`ModelReply`), тексты ответов, задания сабагентам (`AgentAssignment`), отчёты сабагентов (`AgentReport`) и необязательные исходы вызовов `toolOutcomes` (агент, чей хук не отличает неудавшийся вызов, берёт исход из транскрипта: `withToolOutcomes` правит `ok` у событий по `callId`). Типы результатов — `capture/transcript-model.ts`. **Токены и `usage`.** `transcriptsOf` суммирует токены каждого запуска по модели (`DraftMeta.runTokens`: `agentId` → `ModelTokens[]`, сумма — `tokensByModel` в `capture/model-tokens.ts`), а токены основной сессии берёт по сообщениям со временем (`sessionUsages`). `toDraft` ставит на последнюю остановку запуска по одному `usage` на каждую модель, а токены сессии — по одному `usage` на каждую пару (участок между привязками, модель): цена зависит от модели, поэтому разные модели в одно событие не сливаются; `usage` несёт `tokens`, `model` и `breakdown`, их строит `usageEventsOf`. Сообщение без модели образует отдельную группу. `publishBuild` токены не складывает: `usage` сборки остаются на своих местах (стоимость этапа выводится по позиции), без тегов `run` и `project`, с `model` и `breakdown`; время `usage` не идёт назад и не выходит за конец сборки (`usage` в расчёт времени не входит и может стоять до первого события или внутри сжатой паузы; `BuildTimeline.at` не убывает: момент внутри сжатой паузы встаёт в конец оставленной её части), `model` проходит проверку утечек. Черновик старого формата (`usage` без разбивки) публикуется как есть; сумма `tokens` по сборкам равна токенам журнала. **Стоимость в `publish`.** После строки `published` команда печатает стоимость записи из `costOf(briefOf(record)).total` ядра: `publish.cost` (сумма по ценам API и дата цен `PRICES_AS_OF`) или `publish.costUnknown` (текст на каждую причину); деньги форматирует `formatUsd` (`messages/money.ts`: два знака, меньше цента — `< $0.01`). Цены и вывод стоимости — в ядре, кит их не знает. Модель этапа черновик берёт из тех же ответов: станция — первый ответ транскрипта её запуска (`runModels` в `DraftMeta`, по `agentId`), этап из инструментов основной сессии — ответ, внутри которого идёт вызов (первый, закончившийся не раньше вызова, иначе последний: Codex датирует ответ концом хода); это `model` на `stage_enter`, без транскрипта поля нет. Метка задачи — необязательное `task` сборки черновика (её ставит редактор по слову человека), `publishBuild` кладёт её в `data.task`; `model` и `task` проходят проверку утечек. `transcriptsOf(формат, читатель)` даёт `SessionTranscripts`: `inputsOf(события, сообщения)` читает транскрипт сессии и сабагентов (каждый путь — один раз, даже если файл играет несколько ролей; читатель `TranscriptReader` по умолчанию читает файл; исход — `read`, `missing`, `compressed` или `failed`, каждый кроме `read` — предупреждение, а не падение, одно на файл; пропавшие файлы считаются двумя строками — станции и прочие — а транскрипт самой сессии получает свою) и отдаёт `toDraft` события и `DraftMeta`. `draftSession({ capture: { agent, transcripts } })` и `publishSessions({ agent, source })` — общие команды: адаптер зовёт их со своим агентом, транскриптами и `RecordSource`. `to-draft.ts` выводит этапы из таблиц `TOOL_STAGES` (там и `apply_patch` Codex), `COMMAND_STAGES`, `AGENT_STAGES`; `builds.ts`, `draft.ts`, `leaks.ts`, `publish.ts` — сборки, формат черновика, страховка от утечек и сборка записи (`publishBuild`, `publishDraft` получают `source`). Тексты команд, видов утечек и полей шапки — `KitMessages` (`draft`, `publish`, `preview`, `leakKinds`, `headerFields`).
- **Предпросмотр черновика** (`capture/preview.ts`, `commands/preview.ts`). `publishBuild` разделён: `eventsOfBuild` отдаёт события сборки (кому принадлежит событие, решают сборки всего черновика), `recordOfEvents` собирает запись из событий (время, шапка, `parseRecord`), `recordOfBuild` = оба шага, `publishBuild` = `recordOfBuild` + `checkNoLeaks`. Предпросмотр показывает человеку его же сборку, поэтому проверку утечек пропускает: результат нельзя публиковать и писать в журнал. `previewBuild` сперва заполняет пустые поля шапки во всех сборках черновика (проект, harness и процесс из конфига проекта, язык — параметр, название — `preview.untitled(id сборки)`), потом делит события по сборкам на целом черновике и только после этого зовёт `previewEvents` для событий своей сборки: убранное событие не должно переносить остальные в другую сборку. `previewEvents` подставляет там, где редактор ещё не писал, сказанное: первая непустая строка `said` — в `goal` промпта и `line` реплики или вмешательства, весь `said` без пустых краёв — в `text`, обрезка по `RECORD_LIMITS` в кодовых точках; отредактированное и склеенный промпт остаются, событие без текста в `said` и без редактуры выпадает, склеенный промпт без предыдущего промпта тоже. `previewDrafts({ agent, source, language })` читает все `*.json` из `capture/<агент>/drafts/` (нет каталога — `[]`) и ничего не пишет; битый черновик или сборка без событий (`DraftError`, `RecordError`, `KitError`) — предупреждение `preview.skipped` и дальше. Адаптеры оборачивают её своим агентом и источником.
- **Тексты записи** (`templates/`, `generate/template.ts`): `recording-rules.md` (правила чистовой версии, реплик и вмешательств, раздел про несколько задач) и `recording-editor.md` (указания редактору реплик) общие; скилл записи и роль редактора каждый адаптер оформляет под свой формат. Что различается — `RecordingTerms` (`{{feature}}`, `{{publishSkill}}`, `{{interventionWords}}`); `recordingTemplateValues` подставляет их в общие куски раньше, чем куски попадают в шаблон адаптера (`{{recordingRules}}`, `{{recordingEditor}}`). Шаблоны кита, как и шаблоны адаптеров, собирает в бандл `packages/cli/scripts/build.ts`.
- **Команда CLI** (`cli-command.ts`): `CLI_COMMAND` (`npx cyberzavod`) для подсказок человеку и `pinnedCliCommand(harness)` (`npx cyberzavod@<версия>`) для сгенерированных текстов. `NPX_CACHE_FIRST_FLAGS` (`-y --prefer-offline --fetch-retries=0`) — флаги npx «сначала кэш»: пакет берётся из кэша без обращения к реестру, без сети и кэша npx падает сразу; одна строка на оба `HOOK_RUNNER` адаптеров и на запуск цеха.
- **Сообщения** (`messages/`): `KIT_MESSAGES` на английском и русском (`KitMessages`: хук остановки — агент читает его как задачу, хук записи, черновик, публикация и предпросмотр (`preview`), ошибки генерации и черновика). Ошибка кита — `KitError` (`errors.ts`) с `LocalizedText<KitMessages>`, `message` всегда английский. Адаптер описывает её своим каталогом: его `describeError` узнаёт `KitError` и печатает по каталогу кита. `SettingsError` — диагностика формата (английская), адаптер оборачивает её в `unparsedSettings(err, файл)`.
- Новый общий кусок попадает в кит, когда он нужен второму адаптеру; то, что знает один агент, остаётся в адаптере. Кит не называет Claude, Codex, их модели, каталоги и события. Два исключения — таблицы, которые читает общий код и которые поэтому одни на всех. `SERVICE_MESSAGE_PREFIXES` в `capture/service-messages.ts` — начала служебных сообщений всех агентов, по строке на каждого (комментарием отмечено, чьи); `isHumanPrompt` вызывается из общего `recordEvent` и черновика. Таблицы этапов в `capture/to-draft.ts` — `TOOL_STAGES` (имена инструментов агентов: `Edit`, `Write`, `apply_patch`…) и `AGENT_STAGES` (имена станций процесса): по ним черновик выводит этап из действий агента. Новый агент добавляет в обе таблицы свои строки.
- Тесты — на временном каталоге; данные — фабриками.
