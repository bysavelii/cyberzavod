# Сайт (apps/web)

Astro + SolidJS + Nano Stores, слои Feature-Sliced Design. Страницы собираются в статический HTML; JS получают только островки с `client:*`. Цех рисуется на canvas через PixiJS, интерфейс над ним — HTML и Solid.

## Слои FSD

- Слои в `src`: `app` → `pages` → `widgets` → `features` → `entities` → `shared`. Импорт только из слоёв ниже своего.
- `src/pages` — маршруты Astro, они же слой pages: только компоновка виджетов, без логики. Все страницы лежат в `src/pages/[...lang]/` (см. «Языки»). Единственное исключение из направления импортов: страницы подключают layout из `app/layouts`, потому что маршрутизация в Astro живёт в `pages`.
- `features/shared-recording` — запись из галереи на странице `/r/`: модульный стор `$sharedRecording` и `openSharedRecording(search)`; цех и журнал — два острова одной записи, запрос уходит один раз. `features/language-query` — остров `LanguageQuery` без разметки: на страницах с данными в параметрах адреса переносит параметры в ссылки на другие языки (`a[hreflang]`).
- `features/sign-in` — кто вошёл на сайт: модульный стор `$account` (`loading`, `guest`, `author` со своей галереей, `broken`, `failed`), `loadAccount()` (один запрос `GET /api/me` на страницу, как бы много островов его ни спросило) и `reloadAccount()` (после выхода или правки галереи; прежнее состояние держится до ответа, без мигания загрузкой). Острова: `AccountLink` (гостю и при сбое — «Войти через GitHub», автору — аватар и логин со ссылкой в кабинет; пока ответа нет — ничего) и `SignInFailedNotice` (сообщение по `?login=failed`, отметка сразу уходит из адреса).
- `features/journal-sync` — связь журнала сборки с цехом: модульные сторы `$sceneRecordingId` (какую запись проигрывает цех: в серии она меняется) и `$sceneSpeech` (до какой речи он дошёл), `connectScene` (цех подключает сюда свою модель) и `seekScene(recordingId, speech)` (журнал просит перемотку; цех, который уже проигрывает другую запись, не перематывается). Журнал и цех — разные виджеты и друг друга не импортируют.
- Слайс наружу отдаёт только то, что есть в его `index.ts`; глубокие импорты в чужой слайс запрещены.
- Логика, которую можно написать без браузера, идёт в `packages/core`, `packages/player` или `shared/lib` и покрывается тестом.

## Записи

- Записи журнала проекта лежат в `.cyberzavod/journal/<коллекция>/<id>.json` (сейчас `sessions/`) и подключаются через алиас `@journal` (`astro.config.ts`). Читает их только `entities/recording`: шаблон `@journal/*/*.json` берёт ровно один уровень каталогов, поэтому рабочие файлы адаптеров в `capture/` на сайт не попадают; каждая запись проходит `parseRecord`, битая роняет сборку с именем файла. Сайт показывает только сессии (`type: "session"`, `SessionRecord`): название — `data.title`, начало — `timestamp`, проект — `projectId`, события — `data.events`. Адреса и имя слайса остались `recordings`: это публичные URL.
- Страница записи — `/recordings/<id>/` и `/ru/recordings/<id>/`, адрес собирает `recordingUrl(id, locale)`. Запись не переводится: язык страницы меняет интерфейс вокруг неё, а не тексты записи.
- Журнал сборки (`widgets/build-journal`) получает полную запись: промпты, вмешательства и реплики одним списком по времени, у вмешательства и реплики — полный текст. Остров с цехом получает `briefOf(recording)` — без полных текстов реплик и вмешательств, чтобы они не попали в `props` острова и не раздули страницу; цеху нужна только строка над говорящим.
- Блок «Что поймал процесс» (`widgets/build-journal/ui/ReworkSummary.astro`) стоит в журнале страницы записи над списком, под ним — заголовок «Ход сборки». Это статичная разметка без острова и сторов: возвраты записи выводит `reworksOf` ядра (одно место — см. `packages/core/AGENTS.md`), на каждый возврат `ReworkCard.astro` — `Card` с временем и «возврат · <этап>»; если этап что-то сказал, реплика — `Disclosure` (свёрнут: в шапке `line`, внутри полный `text` абзацами), иначе показан общий `reason`. Тексты записи несут `lang` записи. Возвратов нет — «Ни один этап не вернул работу: задача прошла с первого раза». Блок есть только на `/recordings/<id>/`: на `/r/` и в журнале серии его нет.
- Блок «Стоимость» (`widgets/build-journal/ui/CostSummary.astro`) стоит в журнале страницы записи сразу под «Что поймал процесс». Статичная разметка без острова: `h3`, `StatList` и примечание. Данные — `costViewOf(recording, locale)` (`lib/cost-view.ts`), стоимость выводит `costOf` ядра (одно место — см. `packages/core/AGENTS.md`): «Итого», «До первого этапа» (только если там есть расход), затем этапы по `STAGE_LABELS`; сумма строк равна итогу в ядре; на экране строки и итог округляются до центов по отдельности и могут разойтись на цент. Примечание — «по ценам API на <дата `PRICES_AS_OF`>; подписка оплачивается иначе»: сумма не говорит, что человек её заплатил. Если стоимость записи неизвестна (все нынешние записи сайта сделаны без разбивки токенов, у моделей может не быть цены), блока нет: «неизвестна» вместо нуля на странице записи не пишется. Блок есть только на `/recordings/<id>/`: на `/r/`, в журнале серии и в HUD цеха стоимости нет.
- Журнал собран из Solid-частей, общих для всех страниц с журналом: `lib/timeline.ts` (`timelineOf` — промпты, вмешательства и реплики по времени с номерами, как в цехе; `headerOf` — якорь, время и маршрут записи), `EntryBody` (тело записи: промпт с `<details>`, вмешательство и реплика — `SpokenText`), `Paragraphs` (полный текст абзацами: один вид и для `SpokenText`, и для реплики в «Что поймал процесс»), стили списка — `Timeline.module.css`. Список собирают двое: `BuildJournal.astro` на странице записи из журнала проекта — статичная разметка с островами `JournalEntry`, — и `JournalTimeline.tsx` внутри островов `SharedJournal` на странице записи из галереи и `SeriesJournal` в журнале серии (см. «Серия сборок»). Острова создаёт только Astro: Solid-компонент без `client:*` не может держать внутри острова `JournalEntry`, поэтому сам список (`<ol>`, `<li>` и `JournalEntry` с шапкой и телом) повторён в двух местах, а всё, что в нём решается, — общее.
- Каждая запись журнала на странице записи из журнала проекта — остров `client:visible` (`JournalEntry`) со статичным телом в слоте: полные тексты идут слотом, а не в `props`. Пока панель закрыта, записи не видны, и JS журнала не грузится. Подсветка (`aria-current` у `Card`: цех проигрывает эту же запись — `recordingId` — и дошёл до этой речи) и кнопка «показать в цехе» появляются только с JS; без него — прежняя разметка. «Показать в цехе» перематывает цех и закрывает журнал (`popovertargetaction="hide"`), чтобы сцена была видна на любой ширине. Номера промптов, вмешательств и реплик в журнале те же, что у `PromptCue.index`, `InterventionCue.index` и `MessageCue.index`. Вмешательство — запись с меткой «человек · <причина>» (`labelOf(intervention, locale)` из `entities/intervention`, причины — `INTERVENTION_LABELS` в `shared/config/interventions.ts`), строкой и полным текстом; якорь `intervention-<n>` собирает `interventionAnchor`, у реплики — `message-<n>`.

## Галереи: данные из API

- Записи пользователей приходят не из журнала проекта, а из API (`apps/api`) в браузере: сайт статический, и страницы одни на все галереи и записи. Общего списка галерей нет: галерея открывается по ссылке автора. Адреса — с параметром запроса, чтобы работали без правил nginx и в `astro dev`: запись из галереи — `/r/?id=<slug>`, галерея автора — `/gallery/?user=<login>` (без `user` — вступление), личный кабинет — `/me/`; на русском — под `/ru/`. Аналитика (`/stats/`) — обычная статическая страница, в `API_PAGES` её нет. Пути и имена параметров — `API_PAGES` и `QUERY_PARAMS` в `shared/config/routes.ts` (файл без алиасов: его читает и `astro.config.ts`), адреса собирают `sharedRecordingUrl`, `galleryUrl` (`entities/gallery`), `statsUrl` (`entities/recording`) и `cabinetUrl` (`entities/account`), параметр читает `queryParamOf`. В `astro dev` `/api` проксируется на `localhost:8080` (`astro.config.ts`).
- Запросы к API — только в сегментах `api/` слайсов `entities/gallery` (`fetchGallery`, `fetchSharedRecording`, своя галерея `fetchOwnGallery` — `undefined` на 401, `setGalleryPublic`, `deleteOwnRecording`) и `entities/account` (`signOut`); компоненты сами `fetch` не делают. Общее — `shared/api`: `getJson` и `sendCommand` (PUT, POST, DELETE: тело — JSON с `Content-Type: application/json`, ответ не читается — страница потом заново спрашивает API; оба шлют куку только своему сайту, `credentials: "same-origin"`; ответ с ошибкой — `ApiRequestError` со статусом и кодом из `{"error", "message"}`, тело не JSON — `ApiResponseError`), читатели полей ответа (`objectAt`, `stringAt`, `countAt`, `booleanAt`, `arrayAt`: поле не того вида — `ApiResponseError` с местом), состояние данных на странице `Remote<T>` (`loading`, `ready`, `missing`, `broken`, `failed`), `settle` (исход запроса — состояние: 404 — `missing`, ответ не того вида — `broken`, остальное — `failed`), `readyValue` и `remoteNoticeOf` (текст сообщения по состоянию). Типы ответов и разбор — в `model/` слайсов (`parseGallery`, `parseSharedRecording`, `parseOwnGallery`) с тестами. Запись из API проходит `parseRecord` ядра, как записи журнала при сборке: второго описания формата у сайта нет; не сессия или битая запись — `broken` и понятное сообщение.
- Страница записи из галереи (`src/pages/[...lang]/r/index.astro`) — тот же цех и тот же журнал, что `/recordings/<id>/`: острова `SharedFactory` (`widgets/factory`) и `SharedBuildJournal` (`widgets/build-journal`) читают `$sharedRecording`. Пока записи нет — сообщение в поле и в журнале (`noticeOf` из `features/shared-recording`). Карточки проекта у такой записи нет: в HUD — «автор / проект» (`BuildProject`: `url` есть, только если галерея автора открыта, тогда это ссылка на неё). Страница закрыта от поисковиков, как `/gallery/` и `/me/`: `isUnindexedPath` (`shared/config/routes.ts`) ставит им в `BaseLayout` `noindex` вместо `canonical` и `hreflang` и убирает их из карты сайта (`filter` в `astro.config.ts`). Страница галерей одна на всех авторов, поэтому закрыта целиком.
- Страница галерей (`widgets/gallery`): один остров `GalleryBoard` на вступление и на галерею автора, что показывать — решает модель `createGalleryPageModel` по параметру `user`. При сборке параметров нет, поэтому в разметке — «Загружаем…» (`opening`): у пришедших по ссылке автора вступление не мелькает. Без `user` — вступление: галерея открывается по ссылке автора, общего списка нет, и ссылка в личный кабинет. В галерее автора — карточки записей со ссылками на `/r/?id=<slug>` и бейдж для README (`ReadmeBadge` из `entities/gallery`: его показывает и кабинет): картинка `/api/badges/<login>.svg` и строка Markdown `badgeMarkdown(login, siteUrl)` с кнопкой `CopyButton`; адрес сайта — `Astro.site` из `site` в `astro.config.ts`, строка — та же, что печатает `cyberzavod gallery`.
- Жалобы: ссылка «Пожаловаться» на запись (`/r/`, в журнале над списком, когда запись загружена: `SharedJournal`) и на галерею автора (под записями и бейджем: `GalleryBoard`) ведёт на новый issue репозитория по форме `.github/ISSUE_TEMPLATE/report-content.yml`. Адрес собирают `recordingReportUrl(slug, siteUrl)` и `galleryReportUrl(login, siteUrl)` (`entities/gallery`): `template` — `REPORT_TEMPLATE`, поле формы `link` (`REPORT_LINK_FIELD`) заполнено абсолютным адресом записи или галереи на языке по умолчанию. Id поля в форме и константа в коде меняются вместе. Почты и других личных данных в коде нет; issue публичный, поэтому форма просит не цитировать содержимое записи. Ссылка видна всем, и автору тоже: проверка «чужая ли запись» потребовала бы `$account` в островах ради косметики. Удаляет запись и блокирует аккаунт владелец сайта через API (`apps/api/AGENTS.md`, «Управление для владельца сайта»); очереди и хранения жалоб на сайте нет.
- Страница аналитики (`widgets/build-stats`): статическая, считается при сборке сайта из `publishedRecordings` (`BuildStats.astro`), без JS и API. Числа — `StatList`, возвраты по этапам, вмешательства по причинам и исходы — горизонтальные полосы `BarList` из kit. Плашки — из `totalsOf` (сборки, токены, «Средняя стоимость сборки» с пояснением «по N из M сборок» — среднее по сборкам с известной стоимостью (`costTotalsOf`, `averageCostOf`), плашки нет, пока таких сборок нет; «С первого раза» — доля `buildsWithoutReworks / builds` и «N из M», возвраты, вмешательства) и «Проекты» — число проектов (`projectSeriesOf`). Полосы: возвраты — `reworksByStageOf`, вмешательства — `interventionsByReasonOf` (`entities/recording`), исходы — `buildsSucceeded` и остальные сборки; подписи — `STAGE_LABELS` и `INTERVENTION_LABELS`. Что показать, решает `statsViewOf` (`lib/stats-view.ts`): пока сборок нет — заглушка. Один `h1`, под ним пояснение, диаграммы — `h2`. Страница индексируется: это содержимое сайта.
- Переключатель языка на страницах с параметрами адреса ведёт на ту же запись или галерею: остров `LanguageQuery` после загрузки дописывает параметры к ссылкам с `hreflang`. Без JS ссылка ведёт на страницу без параметров.
- Вход через GitHub — обычная ссылка на `/api/auth/github/login?return=<путь страницы с параметрами>` (`signInUrl`, `pathWithoutSignInResult` из `entities/account`), дальше редиректы OAuth и кука сессии; сайт токенов не видит. После неудачи API возвращает на ту же страницу с отметкой `?login=failed`. Аватар — `https://github.com/<login>.png` (`avatarUrl`), API его не хранит.
- Личный кабинет (`widgets/cabinet`, страница `src/pages/[...lang]/me/index.astro`): остров `CabinetBoard` читает `$account`; гостю — объяснение и вход, автору — выход, видимость галереи (`SegmentedControl`), для открытой — ссылка на неё и `ReadmeBadge`, записи «N из 5» с удалением после подтверждения в карточке и подсказка про `npx cyberzavod share <id>` и `npx cyberzavod login`. Действия — модель `createCabinetModel` (`$isBusy`, `$hasFailed`): после любого действия, удачного или нет, кабинет и меню заново узнают, кто вошёл, — например, истёкшая сессия делает автора гостем. Кабинет закрыт от поисковиков (`isUnindexedPath`).
- Вход в аналитику — в панели «Записи» (`GameLayout`), над списком записей сайта: седьмая плитка меню на странице проекта не помещается в строку на 360×740 по-русски (подписи шире плиток), а на 740×360 — по высоте. Вход через GitHub — плитка `AccountLink` в низу меню на широком экране (над строкой «Код» и язык; подпись короткая — «Войти», полная — в доступном имени) и кнопка в панели «Записи» на любом: на узком и низком экране плитки входа в меню нет (`Sidebar.module.css`). Остров плитки ставит `GameLayout` в слот `account` меню: меню — Solid без JS, остров внутри него может создать только Astro.

## Проекты

- Карточки проектов лежат в `projects/<id>.json` в корне репозитория и подключаются через алиас `@projects` (`astro.config.ts`). Читает их только `entities/project`: каждая проходит `parseProject(raw, LOCALES)` и становится `PublishedProject`: `name` и `description` — `{ en, ru }`, по строке на каждый язык сайта, ссылки общие. Битая карточка, карточка без перевода и запись, чей `projectId` не имеет карточки (`UnknownProjectError`), роняют сборку.
- Страница проекта — `/projects/<id>/` и `/ru/projects/<id>/`, адрес собирает `projectUrl(id, locale)`. Это внешняя ссылка «Built at Cyberzavod» из чужих проектов: английский адрес в корне не менять.
- Раскладка страницы проекта — как главной: на поле цех с серией сборок проекта (с первой, по порядку задач) и журнал текущей сборки (см. «Серия сборок»); карточка проекта (`widgets/project-card`), его итоги и сборки по порядку задач — в выезжающей панели «Проект» (см. «Проекты, которые цех собрал с нуля»), кнопка которой есть в меню только на этой странице. Панель сама не открывается.
- Остров цеха получает проект как `ProjectLink` (`projectLinkOf(project, locale)`: название и адрес на языке страницы); пропс `project` цеха — `BuildProject` (`widgets/factory`), у которого адреса может не быть: так его получает и запись из закрытой галереи. Из `@/entities/project` острову нельзя импортировать значения: они затянули бы в клиентский чанк карточки с описаниями.

## Гайды

- Гайды лежат в `guides/<id>.<язык>.md` в корне репозитория, по файлу на каждый язык из `LOCALES`, и подключаются через алиас `@guides` (`astro.config.ts`). Читает их только `entities/guide`: имя файла даёт id и язык (`guideFileOf`: id из строчных латинских букв и цифр через дефис), frontmatter проходит `parseGuideMeta`: `title` и `description` — непустые строки в одну строку, `order` — целое число. `pairTranslations` собирает файлы с общим id в гайд с `translations` на каждом языке. Битый гайд, гайд без перевода на один из языков и переводы с разным `order` роняют сборку: сайт не показывает гайд только на одном языке. Новый гайд — новые файлы, без правок кода.
- Перевод гайда — тот же текст на другом языке: команды, пути и блоки кода не переводятся. Ссылки на страницы сайта в обоих переводах пишутся от корня, без языка (`/projects/<id>/`): язык страницы они получают в готовой разметке (`GuideBody`, `localizeLinks`).
- Тело гайда начинается с `##`: заголовок `h1` рисует страница из `title`. Таблиц в гайдах нет, вместо них списки.
- Страница гайда — `/guides/<id>/` и `/ru/guides/<id>/`, адрес собирает `guideUrl(id, locale)`. Это текст в поле (`widgets/guide-article`: `Panel` с `scrollable`, внутри `Prose`), а не панель поверх цеха: страница не прокручивается, текст прокручивается в панели. Список гайдов — в выезжающей панели «Гайды» (`widgets/guide-list`), кнопка которой есть в меню везде.
- Подсветка синтаксиса в Markdown выключена (`markdown.syntaxHighlight: false`): Shiki красит код цветами своей темы инлайн-стилями, а цвета сайта берутся только из токенов.
- Кнопки «копировать» у блоков кода ставит остров `CopyCode` (`features/copy-code`, `client:idle`): после загрузки он оборачивает каждый `pre > code` статьи в `codeBlockClass()` и монтирует рядом `CopyButton`. Без JS кнопок нет, код читается как обычный блок.

## Языки

- Сайт на двух языках: английский в корне (`/`, `/recordings/<id>/`, `/projects/<id>/`, `/guides/<id>/`), русский под `/ru/`. Язык по умолчанию и список языков — `DEFAULT_LOCALE` и `LOCALES` в `shared/i18n/locale.ts`; встроенный `i18n` Astro не включён: список языков был бы вторым, рядом с `LOCALES`. Новый язык — член `LOCALES`, и компилятор укажет всё, что к нему не готово.
- Маршруты — `src/pages/[...lang]/…`. `getStaticPaths` каждой страницы строится как `LOCALES.flatMap(locale => …)`: `params.lang = localeParam(locale)` (у языка по умолчанию `undefined`, страница лежит в корне), язык приходит в страницу через `props.locale`. Страница собирается из одного файла на оба языка, и язык в ней не вычисляется из адреса. Адреса — `localizedPath(locale, path)` и `recordingUrl`/`projectUrl`/`guideUrl`/`projectLinkOf` с вторым параметром `locale`; `pathWithoutLocale(pathname)` снимает префикс (`GameLayout` берёт путь без языка из `Astro.url.pathname` и отдаёт его `BaseLayout` и `Sidebar`).
- Тексты интерфейса — в словаре `UI_TEXT` (`shared/i18n/ui-text.ts`, группы по месту на странице) и в таблицах `Translated<T>` рядом с данными (`STAGE_LABELS`, `FOREMAN_LABEL`, `INTERVENTION_LABELS`, `LOGO_LINES`, `LOGO_SHORT_LINES`, `site`). `Translated<T>` — `Record<Locale, T>`: без `en` или `ru` у любой записи `astro check` падает. Текст с параметрами — функция в каждом языке; число со словом — `PluralWords` и `formatCount(count, words, locale)`. Строки в компонентах не пишем: всё идёт из словаря, кроме ошибок для разработчика (`throw`, `console.error`) — они русские. Пустую строку и параметр, не дошедший до текста, ловит `ui-text.test.ts`: каждую функцию-лист он вызывает с пробой на каждый параметр (`probe-1`, `probe-2`, …) и проверяет, что все пробы есть в результате. Формы числа в этот тест не попадают, они не функции, а строки `PluralWords`: их выбирает `formatCount`, его проверяет `format.test.ts`.
- Числа, даты и длительность форматируются по языку страницы (`formatTokens`, `formatDate`, `formatDuration` с параметром `locale`, форматтеры `Intl` по `LOCALE_TAGS` через `byLocale`). `navigator.language` нигде не читается: страницы собираются заранее, и язык зрителя им неизвестен.
- Язык в острове — пропс `locale` корня острова (`Factory`, `JournalEntry`, `CopyCode`), дальше `LocaleProvider` и `useLocale()` из `shared/i18n/locale-context.ts`. Entities получают `locale` вторым параметром (`routeOf`, `labelOf`, `recipientOf`).
- Таблички станков и мастера в цехе и логотип в меню — на языке страницы: графика получает язык в `loadFactoryGraphics(locale)`, надписи логотипа — `LOGO_LINES` и `LOGO_SHORT_LINES` в `shared/config/logo.ts`.
- Гайды и карточки проектов переведены: страница и список гайдов берут `translations[locale]` (см. «Гайды»), карточка — `name[locale]` и `description[locale]`. Ссылки на страницы сайта внутри гайда и карточки получают язык страницы (`localizeLinks`, `localizeHref`).
- Записи сборок не переводятся: язык оригинала — `data.language` записи (код ISO 639; у записей до этого поля ядро ставит `ru`). Заголовок, промпты, строки и тексты реплик и вмешательств в HUD, журнале и списке записей несут `lang` записи; если он не совпадает с языком страницы, рядом стоит пометка `languageNoteOf(language, locale)` из `shared/lib/language-note.ts` («recorded in Russian»): в HUD — после даты, в журнале — над списком, в списке записей — после счётчиков. Остров цеха получает пометку готовой строкой в пропсе `languageNote`. Функция лежит в `shared/lib`, а не в `entities/recording`: острова записи из галереи считают пометку в браузере, а `@/entities/recording` затянул бы в клиентский чанк все записи журнала (`import.meta.glob`). Пузыри над станками `lang` не несут: в них рядом с текстом записи подписи интерфейса.
- Переключатель языка — ссылка на ту же страницу на другом языке, с `hreflang`, `lang` и самоназванием языка (`LOCALE_NAMES`: данные языка, а не текст интерфейса, поэтому они лежат в `locale.ts`, а не в `UI_TEXT`). Доступное имя плитки начинается с видимой подписи («RU — Русский», `UI_TEXT.menu.language`): подпись входит в имя (WCAG 2.5.3), `title` — самоназвание. Она есть в панели «О заводе» первой строкой на всех раскладках и в меню на широком экране — в нижней строке рядом с «Код» (раскладка этой строки — в «Игровой экран»).
- SEO. `BaseLayout` ставит `<html lang>`, `canonical` на саму страницу и `hreflang` на каждый язык и `x-default` абсолютными адресами от `site`; карта сайта — `@astrojs/sitemap` с теми же `LOCALES`. Ещё `BaseLayout` ставит иконки, `theme-color`, автора, Open Graph (`og:locale` и `og:locale:alternate`, превью `og:image` 1200×630, `twitter:card`) и разметку schema.org `WebSite` с автором; `robots.txt` (`src/pages/robots.txt.ts`) открывает сайт и указывает карту сайта.
- Картинки сайта — табличка логотипа из меню, собранная при сборке (`shared/lib/site-images.ts`): иконка вкладки `favicon.svg` (короткая табличка `LOGO_SHORT_LINES`), `apple-touch-icon.png` и превью ссылок `preview.png` (полная `LOGO_LINES`) на полу цеха. Маршруты — `src/pages/[...lang]/<имя>.ts`, у каждого языка свои картинки со своей надписью; адреса — `site.images`. Краски берутся из текста `tokens.css` (`readCssTokens`), PNG собирает `sharp`. Картинок в репозитории нет: новая надпись или краска логотипа сама попадает в иконки.
- Страница «не найдено» — `src/pages/[...lang]/404.astro` (`widgets/not-found`, тексты — `UI_TEXT.notFound`). Astro собирает английскую в `/404.html`, русскую — в `/ru/404/index.html`; nginx (`nginx.conf`) отдаёт их с кодом 404 через `map $uri $not_found_page`: под `/ru/` — русскую, иначе — английскую. `GameLayout notFound` закрывает страницу от поисковиков (`<meta name="robots" content="noindex">` вместо `canonical`, `hreflang` и `og:url`: своего адреса у неё нет), а переключатель языка ведёт на главную другого языка. Новый язык — строка в `map`.
- Тест по сборке — `build-tests/` (`pnpm check` гоняет его после `astro build`: `vitest.build.config.ts`). `readBuiltSite(dist, origin)` читает `dist/`, функции `brokenLinks`, `missingAlternates`, `foreignLocaleLinks`, `pagesMissingFromSitemap`, `unindexedPagesInSitemap` отдают список находок (страница с `noindex` не обязана иметь `canonical`, `hreflang` и место в карте сайта и не должна в неё попадать; `<html lang>` и ссылки проверяются у всех); `notFoundFilesOf` (`build-tests/nginx.ts`) читает из `nginx.conf` файлы страниц «не найдено», и `dist.test.ts` проверяет, что они есть на каждом языке и закрыты `noindex`; `built-site.test.ts` проверяет их на маленьких сайтах, `dist.test.ts` — что на настоящем `dist/` находок нет. Новая страница или ссылка, которая уводит на чужой язык, ломает этот тест.

## Состояние: `model` и `ui`

- Состояние, завязанное на логику, — что проигрывается, где мы, что раскрыто, готова ли графика, — живёт в сегменте `model/` слайса на [Nano Stores](https://github.com/nanostores/nanostores): атомы, `computed` и действия-функции. Без Solid и DOM, с тестами на Vitest.
- Сторы называются с `$` (`$playback`, `$scene`). Наружу модель отдаёт их только для чтения (`ReadableAtom`); менять состояние можно лишь её действиями.
- `ui/` — представление: компоненты читают сторы через `useStoreValue` (`shared/lib/use-store-value.ts`) и вызывают действия. Своё состояние в компоненте — только чисто визуальное (наведение, фокус); всё, от чего зависит логика, — в модели.
- `useStore` из `@nanostores/solid` не использовать: он перекладывает значение в Solid-стор через `reconcile` и правит прежний объект на месте. Объекты кадра ядра общие со сценарием — такая правка портила сцену (рабочие места уезжали в проход). Сценарий ядра заморожен, так что правка на месте теперь падает сразу.
- Правила предметной области — в модели как `computed` (например, `$promptPosition`: над кем висит промпт — над мастером, который говорит его у станка; так же `$interventionPosition`), а не в компонентах. Компонент подписывается на узкий стор, который ему нужен, а не на всю сцену.
- Если экземпляров на странице может быть несколько, модель создаётся фабрикой (`createFactoryModel`) и раздаётся компонентам слайса через контекст Solid, а не пропсами. Общее между островками состояние — модульный стор в `model/`.
- Драйверы браузера (requestAnimationFrame, наблюдатели) — в `ui/`: они слушают сторы и вызывают действия модели, логики не содержат.
- Чистые вспомогательные расчёты слайса — в `lib/`, с тестами.

## Игровой экран

- Весь сайт — игровое поле: страница не прокручивается, цех нарисован на всё окно (`app/layouts/GameLayout.astro`). Слева меню (`widgets/sidebar`), справа HUD цеха, длинное содержимое — записи, журнал сборки, проект, гайды, «о заводе» — в выезжающих панелях поверх.
- Главная: над цехом в его колонке, рядом с HUD, — `widgets/home-intro`: что такое Киберзавод одной-двумя фразами, этапы процесса из `STAGES` ядра и `STAGE_LABELS` (те же подписи, что на табличках станков) и кнопка на гайд `getting-started`. Страница передаёт его `SeriesFactory` детьми: `children` у `FactoryFloor` — содержимое над полем, а план вписывается в остаток поля. На узком экране остаются первая фраза и кнопка, на низком блока нет: там цех и полоса HUD занимают всю высоту. Крестик скрывает блок, а переход по кнопке на гайд запоминает, что посетитель его видел: метка в `localStorage` браузера (`model/dismissal.ts`), на сервер ничего не уходит. Встроенный скрипт перед блоком читает метку при разборе страницы и ставит атрибут на `<html>`, поэтому вернувшийся посетитель не видит, как блок мелькает.
- Панели — нативный `popover` (`Drawer` из kit): открываются кнопкой с `popovertarget` без JavaScript, а их содержимое всегда есть в HTML страницы — его видят поисковики. id панелей — в `shared/config/panels.ts`.
- Узкий экран — `(width <= 48rem) and (height > 40rem)`: меню становится строкой сверху, HUD — карточкой снизу. Низкий — `height <= 40rem` (телефон боком; сюда же попадают ноутбуки с невысоким окном): меню остаётся слева и помещается целиком без прокрутки — плитки становятся строкой «иконка + подпись», логотип — короткая табличка «КЗ» («CZ» на английском); HUD лежит полосой под полем на всю ширину справа от меню: полка речи и управление в двух равных колонках. Узкий и низкий вместе — `(max-width: 48rem), (max-height: 40rem)`: так сжимаются kit и HUD, скрывается ярлык `Panel`, HUD уходит под поле, пузыри уступают полке речи, а заголовок сборки и скорость скрыты.
- Больше всего плиток в меню на странице проекта: цех, записи, журнал, проект, гайды, о заводе и ссылка на код. Чтобы они помещались на 360×740 строкой и на 740×360 без прокрутки, на узком экране поля меню меньше, плитки плоские, как вкладки (рамка и тень только у меню), подпись из двух слов переносится, а нижней строки («Код» и язык) нет — ссылка на код и переключатель языка остаются в панели «О заводе» (`Sidebar.module.css`, `Button.module.css`); на низком — отступы плиток и меню минимальные, плитки тоже плоские, а из нижней строки остаётся только «Код»: две плитки «иконка + подпись» в ряд не помещаются в ширину меню. На широком «Код» и язык — плитки `halfTile`, стоят в одной строке пополам (виджет задаёт им только `flex`), поэтому переключатель не прибавляет меню высоты; новую плитку в эту строку не добавлять, а отдельную ставить выше с проверкой высоты. Новая плитка меню — снова проверить оба размера на странице проекта. Английские подписи («Floor», «Builds», «Log», «Project», «Guides», «About») нарочно короткие: длинное слово сначала укорачивают в словаре, а не правят CSS.
- Пороги `48rem` (узкий) и `40rem` (низкий) повторяются в медиазапросах tokens.css, Button, Drawer, Panel, Sidebar, Hud, PlaybackControls, Factory, HomeIntro и GameLayout — переменные CSS в условиях медиазапросов не работают. Менять их — только вместе во всех этих местах.
- Меню, HUD и блок главной лежат над пузырями речи (`z-index: 3` против 2 у `.overlay`): пузырь не закрывает их и не перехватывает нажатия.
- На узком и низком экране пузыри скрыты, а речь показывает полка `SpeechDock` в HUD (на узком — над управлением, на низком — рядом с ним): метка маршрута, «подробнее» и две строки текста постоянной высоты (`Title lines={2}`, строка метки — `--chip-height` из токенов), чтобы поле не прыгало; пока никто не говорит, на ней название сборки. «Подробнее» у промпта показывает главное указание целиком и уточнения в `ScrollArea` не выше `--details-max-height` (`SpeechDock.module.css`, доля высоты окна): дальше они прокручиваются вместе, и HUD не забирает у цеха всё поле. Заголовок сборки на узком и низком экране остаётся в разметке скрытым — это `h1` страницы записи; строка скорости там же скрыта.

## UI-kit (`shared/ui`)

- Внешний вид — только отсюда. Токены (`tokens.css`) — единственный источник краски, контура, «приподнятых» теней, скруглений, шрифтов, шкал кегля и отступов, движения и размеров раскладки; графика цеха читает краски оттуда же. Стиль — яркий тайкун: толстый тёмный контур и жёсткая тень вниз.
- Компоненты: `BarList` (горизонтальная диаграмма на CSS: полоса — доля от наибольшей строки, число текстом рядом), `Button` и `ButtonLink` (вид `primary`/`secondary`/`ghost`/`link`, размер, раскладка `text`/`icon`/`round`/`tile`/`halfTile` — плитка на половину строки меню со своим кеглем и без боковых полей, две такие стоят в ряд, на узком и низком экране она обычная плитка; `buttonClass()` — тот же вид для элементов, которые не могут быть кнопкой, например внутри `<summary>`), `Panel` (`scrollable` — содержимое прокручивается внутри панели), `Prose` (текст статьи из готовой разметки, например Markdown; `codeBlockClass()` — обёртка блока кода с местом под кнопку), `CopyButton` (кнопка «копировать» с итогом на пару секунд; текст читается в момент нажатия; подписи по состояниям — пропс `labels`), `Card` (`current` — текущая карточка списка, `aria-current`), `PixelPlaque` (табличка пиксельным шрифтом табличек цеха в SVG — логотип в меню; глифы и рисунок таблички — `shared/lib/pixel-plaque.ts`, их же берёт графика цеха), `Chip` (в тесной строке или колонке сжимается с многоточием), `Avatar` (круглый портрет автора в контуре, `small` — в плитке, `large` — в кабинете), `GithubMark` (знак GitHub: у lucide фирменных знаков нет), `CopyableCode` (строка кода с `CopyButton` рядом: команда или Markdown бейджа), `Title` (`lines` — блок постоянной высоты на столько строк, лишнее обрезается), `BulletList`, `ScrollArea` (блок на бумаге, содержимое которого прокручивается в высоте, отведённой ему снаружи: прокрутка не уходит на страницу, тень у края показывает, что там есть ещё текст, а пока содержимое не помещается, блок получает фокус, чтобы его можно было прокрутить с клавиатуры), `StatList` (плашки в две колонки, в списке уже 22rem — в одну: значение не переносится; `detail` — пояснение мелким текстом под значением: «4 из 7»), `ChipList` (справочные метки `Chip` строкой с переносом: стек проекта), `Disclosure` (сворачиваемый блок на `<details>`: шапка со стрелкой — слот `summary`, `open` — раскрыт сначала), `Slider`, `SegmentedControl`, `Drawer`.
- Kit не знает словаря: тексты, которые он показывает сам (подпись кнопки закрытия `Drawer.closeLabel`, подписи `CopyButton.labels`), приходят пропсами от того, кто его использует.
- Интерактивное (кнопки, слайдер, переключатели) построено на [Kobalte](https://kobalte.dev) — headless-библиотеке для Solid: клавиатура, ARIA и состояния от неё, вид наш. Новый интерактивный компонент — сначала смотреть, есть ли он в Kobalte. Исключение — `Disclosure`: он на нативных `<details>` и `<summary>`, а не на `Collapsible` из Kobalte, потому что сворачиваются блоки в панелях — статичной разметке без острова; без JS они работают, как `Drawer` на `popover`, а Kobalte потребовал бы гидратации всей панели. В шапке `Disclosure` — только строчный текст: ссылка или кнопка внутри `<summary>` стала бы интерактивным элементом в кнопке, поэтому её ставят рядом, вне шапки.
- Виджеты собираются из компонентов kit и не повторяют их стили: если нужна новая кнопка, плашка, метка или поведение компонента на узком экране — это новый вид компонента в kit, а не CSS в виджете, и виджет не лезет во внутреннюю разметку kit. В CSS виджета — только раскладка (сетка, отступы) и то, что есть только у него.
- Цвета, отступы, кегль и движение — через токены. Собственные размеры компонента (ползунок, значок, расстояние пузыря) — именованные переменные в начале его класса (`--thumb-size: 1.6rem`), а не числа посреди правил.
- Движение (подъём кнопок, выезд панелей) — через токены `--motion-*` и `--*-shift`: при `prefers-reduced-motion` они обнуляются. Подъём при наведении — только под `@media (hover: hover)`.
- В `.astro` класс, переданный в Solid-компонент kit, не получает область видимости Astro и scoped-стиль к нему не применится — оборачивать содержимое в свой элемент.
- Пропсы вида не называть как атрибуты HTML: у `<a>` есть `shape`, у `<button>` — `form`; пересечение ломает типы.
- Иконки — `lucide-solid`, по одной: `import Play from "lucide-solid/icons/play"`.

## Цех (`widgets/factory`)

- `model/` — `playback.ts` (правила проигрывания, чистые функции) и `factory.ts` (модель цеха на Nano Stores: `$recording` (запись в цехе), `$script` (сценарий записи на текущем плане), `$layout` (план из `FACTORY_LAYOUTS`; у сценария своя копия плана, поэтому план сравнивается по `$layout`), `$playback` — производные от одного внутреннего атома, чтобы смена плана или записи была одним изменением и подписчики не видели новый сценарий со старым моментом, `$recordingId` (для журнала), `$scene`, `$recordingTime`, `$prompt`, `$promptPosition`, `$intervention` (вмешательство, которое сейчас говорит мастер у станции, где стоит работа) и `$interventionPosition` (над мастером), `$message`, `$messagePosition`, `$speech` — последний начавшийся промпт, вмешательство или реплика для подсветки в журнале, итоги `$summary` (время, токены, промпты, возвраты, вмешательства текущей записи); среди действий — `play` (пуск стоящей сцены), `seekToSpeech` (перемотка к началу пузыря речи — промпта, вмешательства или реплики — без смены «идёт или пауза»), `setLayout` (сценарий строится заново на другом плане, а момент записи, «идёт или пауза» и скорость сохраняются через `carryTime`) и `load` (другая запись на том же плане с начала: скорость и «идёт или пауза» сохраняются, уточнения промпта закрываются)). `FactoryFloor.tsx` выбирает план по форме поля и экрана (`layoutFor`, экран — размер холста на всё окно) при монтировании и при каждом замере; у поля без площади план остаётся прежним. `lib/speech-timeline.ts` — промпты, вмешательства и реплики сценария одним списком по началу (`speechTimeline`, `speechAt`, `speechStart`).
- `graphics/` — как цех нарисован. Модель и компоненты знают только интерфейс `FactoryGraphics` (`mount`, `setLayout(layout)`, `render(scene)`, `resize(width, height, frame)`, `toScreen`, `destroy`): пол — на весь холст, план — вписан в поле `frame` между меню и HUD; `setLayout` заменяет неподвижный план (пол, станки, кабинет), а вписывает его следующий `resize`; рабочие, мастер и деталь остаются. Новая графика (спрайты, 3D) — новая реализация, которую возвращает `loadFactoryGraphics(locale)`; остальное не меняется. PixiJS импортируется только здесь и только динамически — отдельным чанком.
- Pixi подключается без `Application` и автозагрузки расширений (`manageImports: false`): WebGPU, события, accessibility, DOM и фильтры Pixi в чанк не попадают. Нужное расширение подключается явным импортом `pixi.js/<модуль>` в графике.
- `graphics/pixel/` — цех в пиксель-арте. Рисунки — массивы строк в коде, буква — краска (`art.ts`: `ART_LEGEND`, `paintArt`); при встраивании (`mount` и `setLayout`) они красятся токенами из `palette.ts` (своих красок в коде нет: белый и каска мастера — тоже токены из блока графики цеха, тени и блики — ступени `shade()`) и запекаются в текстуры (`textures.ts`: `CanvasSource` с `scaleMode: "nearest"`, единственное место с DOM-холстом). PNG-атласа нет: ни загрузчика, ни лишнего запроса. Клетка — 16 пикселей рисунка на единицу плана (`units.ts`), множитель экрана целый в пикселях устройства (`fitPixelPlan` в `bounds.ts`, рендерер без сглаживания, `resolution` равен `devicePixelRatio` без потолка, у холста `image-rendering: pixelated`). Спрайты не поворачиваются: `heading` квантуется в 4 стороны (`frames.ts`: вниз, вверх, вбок; влево — зеркало), объекты сортируются по `y`. Поза человека и такт станка тоже выводятся из кадра сцены в `frames.ts`: шаг, шаг с деталью (`carryA`/`carryB`), руки вперёд при передаче (`reach`), удар у станка (`workA`/`workB`, `WORK_FRAME_MS`), жест мастера, пока он говорит (`talkA`/`talkB`, `TALK_FRAME_MS`); слушающий мастер стоит. `machineWorkOf` даёт станку тот же такт, что рабочему, и покой, когда рабочий не бьёт; новая поза — строка в `ACTOR_ART` (по рисунку на каждую сторону) и в `ACTOR_POSE_IN_PLACE`. Остальное: `floor.ts` (плитка до краёв, проход прямоугольниками — только по горизонтали и вертикали, `lane.ts` бросает ошибку на диагональ; площадки), `machines.ts` (станок — рисунок на этап в таблице `MACHINE_ART`, лампа отдельными спрайтами; работа станка — накладка на каждый такт `WorkBeat` в таблице `MACHINE_WORK_ART`, в ней только пиксели, которые отличаются от корпуса, — это проверяет тест; накладки лежат поверх корпуса и под лампой, `showMachineWork` меняет только их видимость; новый такт в `machines.ts` — только рисунок в `MACHINE_WORK_ART`), `office.ts` (стол кабинета), `plaques.ts` и `glyphs.ts` (таблички пиксельным шрифтом: глифы строками и рисунок таблички — в `shared/lib/pixel-plaque.ts`, только заглавная кириллица и латиница из названий этапов, мастера и логотипа; место таблички считают и рисование, и `planBounds`), `actor-art.ts` (рисунки человека 16×16: все стороны и позы, полными фигурами), `actors.ts` (рабочие, мастер, деталь; деталь в руках лежит над несущим, когда тот смотрит вниз, и под ним, когда вверх или вбок, чтобы руки были поверх ящика: слой выводит `crateLayerOf` из кадра по таблице `CARRIED_IN_FRONT` и отстоит от слоя несущего на полпикселя, чтобы не встать между ним и соседом; мастер — тот же человек своего цвета и в белой каске; кадры всех поз запекаются заранее по `ACTOR_ART`, и `destroy` освобождает их все, а не только висящие на спрайтах; `ACTOR_FIGURE`, по которой таблички обходят людей, считается по всем сторонам и позам на месте, с поднятыми руками), `renderer.ts` (выбор рендерера: WebGL, без него Canvas). Новый этап или новая буква на табличке — новая строка в таблице.
- Названия этапов и мастера (`STAGE_LABELS`, `FOREMAN_LABEL`, оба `Translated`) — в `shared/config/stages.ts`: их берут и таблички станков на языке страницы, и маршруты реплик (`entities/message`: «Код → Проверки» и «Code → Verify», «Постановка → мастер» и «Plan → foreman»). В коде мастер — `foreman`.
- `ui/` — `FactoryFloor.tsx` по готовой модели собирает графику и часы, подключает модель к журналу (`connectScene`) и меряет поле; `Factory.tsx` ставит в него модель одной записи, `SeriesFactory.tsx` — серию сборок (см. «Серия сборок»). `Hud` (запись и счётчики сборки из `$recording` и `$summary` модели: время, токены, промпты, возвраты, вмешательства; в серии рядом с проектом — «сборка 2 из 7»), `SpeechDock`, `PromptBubble`, `InterventionBubble`, `MessageBubble`, `PlaybackControls` только отображают (рамку, расположение и хвостик пузыря к говорящему даёт общий `SpeechBubble`; «подробнее» у реплики и вмешательства ставит паузу и открывает журнал на них через `open-journal.ts`: `showMessageDetails`, `showInterventionDetails`; прокрутка к записи идёт после открытия панели, а если записи в журнале ещё нет — когда она появится; запись встаёт к верху журнала, чтобы у длинной реплики были видны шапка и начало); `frame-clock.ts` двигает модель по кадрам, пока сцена идёт, цех виден и вкладка открыта. При `prefers-reduced-motion` (`reduced-motion.ts`) сцена стартует на паузе.
- Кадр рисуется по подписке на `$scene`: идёт сцена — каждый кадр, стоит — только после перемотки и смены размера. В кадре не создаются объекты: у готовых спрайтов меняются текстура кадра, место, зеркало, видимость и `tint`; рисунки запекаются в текстуры при встраивании.
- Текст (промпты, вмешательства и реплики над говорящими) — HTML поверх холста: он чёткий, доступен и раскрывается по клику.
- Пузырь не выходит за поле. По высоте `placeBubble` (`lib/bubble-placement.ts`) раскрывает его туда, где до края поля больше места, и отдаёт это место (`roomHeight`, считает `verticalRoomOf`); `SpeechBubble` ставит его в `--room-height`, и пузырь не выше. По ширине пузырь не шире поля (`--field-width`) и стоит серединой над говорящим, а у края поля прижимается к нему: сдвиг считает `bubbleLeftOf` по ширине пузыря, которую `SpeechBubble` меряет `ResizeObserver`, хвостик при этом смотрит на говорящего и не заходит на скругление угла. Метка, текст и раскрытые уточнения (`children`) лежат в `ScrollArea` и прокручиваются вместе, а кнопки (`actions`: «подробнее», «свернуть») стоят под ними и видны всегда: на узком поле закреплённое указание заняло бы всю высоту и не оставило места уточнениям. Сам пузырь не прокручивается, иначе обрезался бы хвостик.

## Серия сборок

- Главная и страница проекта проигрывают серию по кругу: сборки проекта по порядку задач, затем сборки следующего проекта, и снова с первого; на странице проекта — только его сборки, с первой. Порядок — только `projectSeriesOf` (`entities/recording`). Страница записи `/recordings/<id>/` и `/r/` — один `Factory`, как раньше.
- Остров `SeriesFactory` (`widgets/factory`) получает сборки готовыми пропсами `SeriesBuild`: их собирает страница в `.astro` через `seriesBuildsOf(recordings, project, locale)` — запись `briefOf`, проект `BuildProject`, пометка о языке и место среди сборок проекта `{ index, count }` (`index` с нуля). Значения из `@/entities/recording` и `@/entities/project` острову импортировать нельзя. Полные записи всех сборок серии в пропсы не идут — только `briefOf`.
- Серия — `model/series.ts`: `createFactorySeries(builds)` создаёт модель цеха на первой сборке; `$current` — сборка, которая сейчас в цехе (по `$recordingId` модели); `follow()` следит за `$playing` и, когда сцена сама встала в конце записи (`isAtEnd` из `playback.ts`), ставит следующую по кругу (`nextIndexInCircle`, `shared/lib/circle.ts`) через `load` и пускает её `play`. Пауза человека ставит сцену раньше конца, а перемотка на паузе её не пускает — серия ждёт; перемотка назад на ходу не мешает: запись доиграет, и серия пойдёт дальше. При `prefers-reduced-motion` `SeriesFactory` не вызывает `follow`: сцена стартует на паузе и сама к следующей сборке не переходит. Холст и графика при смене записи остаются — меняются сценарий в модели и HUD (`UI_TEXT.series.buildOf`: «сборка 2 из 7», номер с единицы). Подписи HUD, которые зависят от сборки, строятся в JSX заново при каждой смене: колбэк `<Show>` без `keyed` Solid вызывает один раз, и строка из него осталась бы от первой сборки.
- Журнал серии — остров `SeriesJournal` (`SeriesBuildJournal.astro`, `client:idle`): полная запись той сборки, что сейчас в цехе (`$sceneRecordingId`; пока цех не подключился — первая сборка серии), и заранее — следующей (`model/series-journal.ts`, `createSeriesJournal`). В панели всегда одна запись, поэтому якоря `message-<n>` и `intervention-<n>` однозначны. Новую сборку журнал показывает с начала (`ui/journal-scroll.ts`): браузер помнит прокрутку закрытой панели, поэтому журнал прокручивается в начало при открытии панели, если сборка сменилась с тех пор, как её видели, или сразу, если панель открыта. Пока записи нет — сообщение `seriesJournalNoticeOf` (`lib/series-notice.ts`); без JS в панели только оно.
- Полные записи журнал берёт файлами `/recordings/<id>.json`: статический эндпоинт `src/pages/recordings/[id].json.ts` по `publishedRecordings` — вне `[...lang]`, потому что запись не переводится; это не страница, и `@astrojs/sitemap` в карту сайта его не берёт (туда идут только маршруты-страницы). Грузит их `entities/recording-file` без `import.meta.glob`: `fetchRecording(id)` (`getJson` из `shared/api` → `parseRecordingFile`: `parseRecord` ядра и проверка, что это сессия, иначе `ApiResponseError`), адрес — `recordingFileUrl(id)`, кеш на страницу — стор `$recordingFiles` (`Remote<SessionRecord>` по id) и `requestRecordingFile(id)`: каждая запись спрашивается один раз, после сбоя сети — снова при следующем запросе.

## Проекты, которые цех собрал с нуля

- Записи сайта — сборки проектов, которые цех собрал с нуля: это примеры, а не галереи пользователей. Списки, итоги и аналитика (`/stats/`) строятся при сборке сайта из `publishedRecordings` и карточек, без API: записи сайта и есть аналитика. Порядок проектов и сборок — только `projectSeriesOf` (`entities/recording`): проекты — в порядке, в каком завод за них брался, сборки — по порядку задач, номер сборки — её место в этом списке с единицы.
- Итоги — `totalsOf(recordings)` (`entities/recording/model/totals.ts`): суммы `summarize` ядра по записям — `builds`, `durationMs`, `tokens`, `prompts`, `reworks`, `buildsWithoutReworks` (сборки, прошедшие все этапы с первого раза), `buildsSucceeded` (сборки, закончившиеся успехом), `interventions`. Средние — `averagePerBuild(totals, count)`: частное без округления, у итогов без сборок — 0; участие человека — `humanInputOf` (промпты и вмешательства вместе). Стоимость — `costOfRecording(recording)` (сумма в долларах или `undefined`, если неизвестна), `costTotalsOf(recordings)` (`entities/recording/model/costs.ts`: `builds`, `buildsWithCost`, сумма только по известным) и `averageCostOf` (среднее по сборкам с известной стоимостью, `undefined`, если таких нет). Деньги — `formatCost(usd, locale)`: доллары с двумя знаками, положительная сумма меньше цента — «< $0.01» (`UI_TEXT.cost.underCent`). Округляют функции вида: время — `formatDuration` до секунд (`formatClock` — часы шкалы, время записей журнала и подписи «показать в цехе» — округляет секунды так же, чтобы итог в HUD и конец шкалы совпадали).
- Панель «Записи сборок» (`widgets/recording-list`, `RecordingsByProject` в `GameLayout`): над блоками — ссылка на аналитику и вход; дальше по блоку на проект (`Card`). Шапка блока — название `h3` со ссылкой на страницу проекта и стек `ChipList`; итоги «N сборок · время · токены» — шапка `Disclosure`: она сворачивает описание, ссылку на репозиторий и сборки (`ProjectBuilds`). Блоки открыты. Ссылка на проект стоит над `Disclosure`, а не в его шапке: в `<summary>` она была бы интерактивным элементом в кнопке.
- `ProjectBuilds` — сборки одного проекта нумерованным `<ol>` по порядку задач: заголовок-ссылка на запись (`lang` записи), день, время, токены, промпты и пометка о языке. Тот же список — в панели «Проект».
- Панель «Проект» на странице проекта: `ProjectCard`, «Итоги» — `ProjectTotals` (`widgets/project-totals`: `StatList` из `projectTotalsOf(totals, stageReworks, locale)` — сборки, время всего и в среднем на сборку, токены, «С первого раза» — доля сборок без возвратов (`buildsWithoutReworks / builds`) с пояснением «4 из 7», возвраты с разбивкой по этапам в пояснении «Ревью 17 · Проверки 1» (`reworksByStageOf`, `entities/recording`: этапы в порядке `STAGES`, без нулевых; пояснение пишет `stageReworksDetailOf` — то же в колонке сравнения; без возвратов пояснения нет), участие человека с пояснением «8 промптов · 1 вмешательство»), «Сборки по порядку задач» — `ProjectBuilds`. Заголовки разделов — `h3` под `h2` панели; у проекта без сборок итогов нет.

## Сравнение прогонов

- Метка задачи — `data.task` записи (необязательная, правило как у `id`; см. `packages/core/AGENTS.md`): записи с одной меткой — прогоны одной задачи, которые прошли один процесс на разных агентах и моделях. Метка глобальная по сайту, а не в пределах проекта: прогон другого агента может жить в другом проекте со своим `projectId`. Метки нет у записей, пока её не назвал человек при публикации.
- Сравнением метка становится при двух записях и больше (`MIN_COMPARED_RECORDINGS`); одиночная метка страницы не даёт. Группы и порядок — `taskComparisonsOf` и `comparisonOfRecording`, название сравнения — `comparisonTitleOf` (название первого прогона) (`entities/recording/model/comparison.ts`): прогоны по порядку `oldestFirst`, метки — по началу первого прогона.
- Страница — `/comparisons/<метка>/` и `/ru/comparisons/<метка>/`, адрес собирает `comparisonUrl(task, locale)`; `src/pages/[...lang]/comparisons/[task].astro` строит её при сборке для каждой метки с двумя записями и больше, меток нет — страниц нет. Это текст в поле, как гайд: `Panel scrollable` (`widgets/build-comparison`, статичная разметка без острова), на узком экране колонки встают одна под другой.
- Колонка прогона — `comparisonColumnOf(recording, locale)` (`widgets/build-comparison/lib/comparison-view.ts`): название-ссылка на запись (`lang` записи), проект, день, агент, процесс и версия harness (расхождение процесса видно глазами, сайт его не проверяет), модели по этапам и счётчики `StatList` — время, токены, стоимость (`formatCost` или «неизвестна»: колонки читаются рядом), возвраты с разбивкой по этапам, итог. Агент всех этапов записи — её `source` (проект ведёт один агент): `AGENT_NAMES` (`shared/config/agents.ts`) называет известных (`claude`, `codex`), незнакомый показывается как есть, `manual` — «вручную». Модели этапа выводит `stageModelsOf` ядра, имена — `formatModel`, несколько моделей одного этапа (доработка ушла на другую) — через « → », этап без названной модели — «модель неизвестна».
- Ссылка на сравнение — `ButtonLink` «Сравнить прогоны этой задачи» в журнале страницы записи над «Что поймал процесс» (`comparisonUrl` — необязательный проп `BuildJournal`, страница записи считает его через `comparisonOfRecording`). На `/r/`, в журнале серии, в списках и панели проекта её нет. Повторный прогон с тем же `projectId` остаётся обычной сборкой в серии и итогах проекта.

## Компоненты

- Интерфейс — Solid (`.tsx`), статичная разметка — `.astro`. Директиву `client:*` ставить только там, где нужна интерактивность. Solid-компонент без `client:*` рендерится в статический HTML — так kit используется и в `.astro`.
- В Solid компонент выполняется один раз: производные значения — функции или `createMemo`, а не переменные; пропсы не деструктурировать, иначе теряется реактивность.
- Стили — CSS-модули рядом с Solid-компонентом, `<style>` внутри `.astro` (Astro ограничивает его компонентом); значения — токены kit.

## Импорты

- Между слоями и слайсами — через `@/…`, внутри слайса — относительные.
- Публичный API слайса подключается по папке (`@/widgets/factory`, `@/shared/ui`), отдельные файлы — с расширением `.ts`/`.tsx`.
